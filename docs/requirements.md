> **生成日期**: 2026-04-12  
> **唯一输入依据**: 本文件（后续 OpenSpec 实施以此为准，不依赖对话上下文）

## 一、验收标准列表（可逐条核查）

| 编号 | 验收项 | 核查方式 |
|------|--------|----------|
| HS-01 | **参数校验覆盖**：所有 SDK 公共方法的外部输入参数必须经过统一校验层 | 检查 `sdk/` 目录下所有公共方法是否存在统一参数校验调用 |
| HS-02 | **错误码规范**：统一错误码格式为 `MODULE_ERRCODE`（如 `FILE_INVALID_PATH`） | 检查错误响应中 Code 字段是否符合规范 |
| HS-03 | **测试覆盖率**：新增参数校验单元测试，覆盖率 ≥ 80% | 运行 `go test -cover` 检查覆盖报告 |
| HS-04 | **路径安全**：文件路径必须经过白名单/规范化校验，禁止路径穿越 | 代码审查 + 单元测试用例 |
| HS-05 | **类型安全**：所有类型断言必须使用安全的辅助函数，禁止直接 `.(type)` 断言 | `grep -r '\.(string|float64|bool)' sdk/` 应无匹配 |
| HS-06 | **分页限制**：`page` 范围 [1, 1000]，`size` 范围 [1, 100] | 检查分页参数的校验逻辑 |
| HS-07 | **随机数安全**：所有涉及安全的随机数必须使用 `crypto/rand` | 检查 `math/rand` 替换为 `crypto/rand` |
| HS-08 | **默认值注入**：可选参数必须在统一层注入默认值 | 检查方法是否存在默认值处理逻辑 |
| HS-09 | **错误响应统一**：所有方法返回 `StandardResponse` 或明确的错误类型 | 代码审查返回类型一致性 |
| HS-10 | **无 panic 风险**：所有潜在 panic 场景（空指针、越界）必须防护 | 静态检查 + 单元测试覆盖 panic 场景 |

## 二、高危漏洞清单（按优先级排序）

### 高优先级（必须修复）

| 编号 | 漏洞类型 | 位置 | 风险描述 | 影响范围 |
|------|----------|------|----------|----------|
| VULN-001 | **路径穿越 (Path Traversal)** | `sdk/file.go:814` | `os.Open(filePath)` 未校验路径，攻击者可通过 `../../../` 读取任意文件 | `UploadFile`、`DownloadFile` 等文件操作 |
| VULN-002 | **类型断言 panic** | `sdk/*.go` 多处 | `data["field"].(string)` 未做类型检查，异常数据可导致 panic | 所有解析 API 响应的代码 |
| VULN-003 | **类型断言 panic（分页参数）** | `cmd/main.go:1054` | `strconv.Atoi(args[1])` 未处理转换失败 | CLI 命令参数解析 |

### 中优先级（建议修复）

| 编号 | 漏洞类型 | 位置 | 风险描述 | 影响范围 |
|------|----------|------|----------|----------|
| VULN-004 | **可预测随机数** | `sdk/share.go:51-52` | 使用 `math/rand` 生成随机数，种子可预测 | 提取码生成、任务调度 |
| VULN-005 | **分页参数未限制** | `sdk/share.go:533-539` | `page, size` 未校验范围，可能导致数据库慢查询或内存溢出 | `GetMyShareList` |
| VULN-006 | **空指针/越界访问** | `cmd/main.go:359-387` | `extractPathFromJSON` 未校验数据结构完整性 | 管道模式数据处理 |

### 低优先级（优化）

| 编号 | 漏洞类型 | 位置 | 风险描述 | 影响范围 |
|------|----------|------|----------|----------|
| VULN-007 | **正则表达式注入风险** | `sdk/share.go:19-22` | 正则表达式处理外部输入，未转义特殊字符 | `GetShareInfo` |
| VULN-008 | **路径处理不一致** | `sdk/*.go` 多处 | `normalizePath`、`stripQuotes` 等函数分散使用，逻辑重复 | 所有路径处理 |

## 三、参数处理规范边界

### In-Scope（包含范围）

| 层级 | 处理内容 | 说明 |
|------|----------|------|
| **校验层 (Validation)** | ✅ 参数非空检查 | 检查必填参数是否为空 |
| | ✅ 类型校验 | 确保参数类型符合预期 |
| | ✅ 格式校验 | 如路径格式、FID 格式、邮箱格式等 |
| | ✅ 范围校验 | 如分页参数范围、数字区间等 |
| **默认值注入** | ✅ 可选参数默认值 | 为未传入的可选参数提供默认值 |
| | ✅ 零值处理 | 将零值转换为合理默认值 |
| **错误响应格式** | ✅ 统一错误码 | `MODULE_ERRCODE` 格式 |
| | ✅ 错误消息规范 | 中英文消息、日志友好格式 |
| | ✅ 错误分类 | 校验错误、业务错误、系统错误 |
| **路径规范化** | ✅ 路径标准化 | 统一处理 `/` 分隔符 |
| | ✅ 相对路径解析 | 处理 `.`、`..` 等相对路径符号 |
| | ✅ 路径安全检查 | 防止路径穿越攻击 |

### Out-of-Scope（不包含范围）

| 层级 | 不处理内容 | 原因 |
|------|-------------|------|
| **HTTP 传输层** | ❌ 请求头、Cookie | 由现有 `makeRequest` 统一处理 |
| | ❌ 超时控制 | 由 `HttpClient.Timeout` 配置 |
| | ❌ 重试逻辑 | 由调用方决定 |
| **业务逻辑层** | ❌ 业务规则校验 | 如分享权限、容量限制等保留在业务代码 |
| | ❌ 业务错误处理 | 业务特定的错误处理逻辑 |
| **日志/监控** | ❌ 访问日志 | 横切关注点，应通过中间件处理 |
| | ❌ 性能监控 | 横切关注点 |
| **序列化层** | ❌ JSON 序列化 | 由现有的 `parseResponse` 处理 |
| | ❌ 反序列化 | 由现有的 `parseResponse` 处理 |

## 四、实施约束

1. **向后兼容性**：重构不得破坏现有 API 的调用方式
2. **渐进式实施**：允许分阶段 rollout，每个阶段可独立验证
3. **文档同步**：更新后的参数要求需在方法注释中明确说明
4. **测试先行**：每个参数校验逻辑需配套单元测试

## 五、定义与术语

| 术语 | 说明 |
|------|------|
| **参数处理层** | 统一的参数校验、默认值注入、错误响应封装层 |
| **StandardResponse** | SDK 统一的响应结构：`{Success, Code, Message, Data}` |
| **错误码格式** | `MODULE_ERRCODE`，如 `FILE_INVALID_PATH`、`USER_NOT_FOUND` |
| **路径穿越** | 通过 `../` 等方式跳出预期目录的攻击方式 |
